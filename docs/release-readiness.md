## 持续采集与生命周期

使用构建后的现代 IIFE，在 Node.js 22 / happy-dom 中模拟 fetch 与 WebSocket，单窗口连续运行 60.278 秒，完成 6 次创建/清空/销毁：

| 项目 | 结果 |
| --- | --- |
| 日志调用 | 5360 |
| 请求 | 268 |
| 实时发送/接收消息 | 10720 |
| 保留上限 | 日志 200、请求 100、活动 1000，检查通过 |
| 可见节点 | 日志不超过 300、网络不超过 100，检查通过 |
| 每次销毁后 | host 移除，current 清空，诊断定时器为 0，console/fetch/WebSocket/history/XHR 原接口恢复 |

初次检查发现真实缺陷：日志容量不超过 200 时，trim 事件先于 add 发出，界面可能创建重复的新行。已修复，并增加每次追加都断言节点数量和顺序的 1000 次回归测试。

### 内存观察的限制

在强制 GC 后，模拟环境堆样本仍由约 31.64 MiB 增至 91.24 MiB。没有把这个结果判为“内存稳定”。额外运行约 20.7 秒并检查 V8 堆快照，发现约 640188 个 `{ result }` 缓存对象，强引用路径指向 `Window → document → Symbol(affectsCache)`；该路径对应 happy-dom 查询缓存实现。该快照未发现构建中 GravScope 类实例残留。

这是对模拟环境增长来源的定位，不是实际浏览器/手机无泄漏证明。真实浏览器 30–60 分钟内存、帧率、后台恢复仍未验收。没有修改或清空模拟器缓存来制造稳定结果。

复现：先运行 npm run build，然后运行 `npm run check:soak -- 1`；30 分钟检查用 `npm run check:soak -- 30`。可通过脚本第三个参数指定 JSON 路径，再追加 --snapshot 保存堆快照。脚本的 checksPassed 仅指数量/生命周期断言，不包含内存稳定结论。
